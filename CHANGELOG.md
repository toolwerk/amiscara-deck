# Changelog

Alle nennenswerten Änderungen stehen hier, nach [Keep a Changelog](https://keepachangelog.com/de/1.1.0/). Versionen folgen SemVer.

## [Unreleased]

### Changed

- CI runs on the local self-hosted runners (Linux, macOS) instead of the hosted ones (#85)

### Fixed

- Deck could not stay quiet in a Focus mode: macOS tells it nothing without a permission it does not have. Deck now brings a Focus filter ("Amiscara Deck", "Still bleiben") the user adds to a Focus; the settings explain it and show when it is active (found in the hand test)
- After a restart of the daemon, a request that had already been answered where the agent runs stayed on the card until the end of the turn
- Several questions of an agent come one after the other on the card ("Frage 1 von 3", "Weiter", "Zurück") instead of all at once
- The last task of an agent shows a shell command typed into Claude Code as the command only, not with its tags, output and terminal control codes
- Questions of an agent (`AskUserQuestion`) and plans waiting for approval (`ExitPlanMode`) were offered like permissions: "Erlauben" answered a question without any answer. Plans are never held; a question is answered with its choices (see above) (found in the hand test)
- After an answer from Deck the agent shows "arbeitet" at once instead of "wartet" until its next event
- The panel under the menu bar symbol collapsed the list to a sliver: it now grows with its agents, at least three are visible, and it scrolls only beyond its limit
- The context fill lagged one message behind: Claude Code writes the last message of a turn after the `Stop` hook, so the daemon looks into the transcript again shortly after (found in the hand test)
- Hidden characters in the rule, the target and the tool name of a request are escaped on the card, like the command; the raw suggestion still goes back unchanged (security review)

### Added

- Release scripts: `scripts/release.sh` builds, signs with Developer ID (helpers included, checked), notarizes, staples and zips the app; `bump-build.sh` and release notes from the changelog (`docs/release.md`); README rewritten for the public, third-party schema removed (#66, #67, #69)
- Extra signals, each with its own switch in the settings: a floating window with the waiting agents that opens by itself without taking the keyboard (buttons answer only after a moment), a sound, one reminder after a minute, the number of waiting agents next to the menu bar symbol (on by default) and a blinking symbol. Window, sound and reminder follow the daemon's notifications, so "Automatik" and Focus modes hold for them
- The panel and the settings say when macOS does not show the notifications of Deck and open the right page of the system settings; a tap on a notification opens the window with what is asked (found in the hand test)
- A right click (or control click) on the menu bar symbol opens a menu with "Fenster öffnen", "Einstellungen" and "Beenden"
- Answer questions of an agent in Deck: the card shows each question with its choices (single or several), several questions come one after the other ("Weiter", "Zurück"), and "Antworten" sends them to Claude Code as if typed there; the question stays open where the agent runs too, and whoever answers first counts. "Allow" never answers a question, a notification only offers "Ansehen", and the answers go into the log of decisions
- Costs: the daemon reads the `cost-state` line of the transcript, keeps what today cost per session in a private ledger and tells every UI; the panel and the window show "Heute ≈" and the detail column the cost of a session, marked as an estimate of Claude Code; own context windows go in `context-windows.json` in the data folder (#63, #64, #65)
- Approvals for Codex (off by default): Deck holds a Codex request only when it would notify about it, since Codex shows its dialog only after the hook ends, and gives it back as soon as the user is at the terminal; the Codex hook entry gets the long timeout from the start, and removing Deck's entries keeps the places of foreign ones because Codex ties its trust to the position (#60, #61, #62)
- Several daemons in one app: add other machines in the settings (host, user, key file or SSH agent, socket); their agents join the list with the host name on the card, answers go to the daemon that owns the request (request ids are prefixed per machine), presence is reported to every daemon, an unreachable machine is retried and named in the panel, an unknown host key waits for the user's yes, a changed one is never trusted (#55, #56, #57, #58, #59)
- Remote transport (`deck-remote`): sign in over SSH with `amiscara-ssh`, open a `direct-streamlocal` channel to the socket of the daemon on the other machine and speak the same protocol; `deck_client::Client::over` takes any stream (#52, #53)
- Hand test list for stage 1 (`docs/handtest.md`) (#51)
- tmux focus for "Automatik": with the terminal in front but the tmux pane of the agent hidden (another pane or window, no client attached), Deck notifies; an unknown answer from tmux changes nothing (#46)
- Codex read only: the settings install and remove Deck's hooks in `~/.codex/hooks.json` (SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PermissionRequest, Stop, SessionEnd) with a note to confirm them once via `/hooks`; foreign entries stay untouched (#48)
- History per agent (up to 30 lines), a private log of decisions (`decisions.jsonl`), retention setting (1 to 365 days, default 7) and clearing of both (#42)
- Minimum version: the settings show the installed Claude Code version and warn when it is older than the tested 2.1.331 (#50)
- Context fill from the transcript (`deck-usage`): last main-agent message, window by model, empty on any read error (#47)
- Settings window: mode and wait time, install and remove the hooks in Claude Code, start at login, retention and clearing of the history (#41)
- Main window with agent grid, status filter and a detail column (request, last task, history, key figures), opened from the panel (#38, #39, #40)
- The app reports presence to the daemon after every connect and when something changes, and takes a notification back when the daemon says the user is at the terminal again (#36)
- Automatic notifications in the daemon: the switch and the steps of "Automatik" decide when a held request is worth a notification with buttons (screen locked, away more than 2 minutes, or another app than the agent's terminal in front; the terminal is found by the path of the app bundle among the processes above the agent). A Focus mode is never broken through, even in "always in Deck". With several UIs only the one where the user typed last gets it, and it moves along. It is taken back when the user returns to the terminal, a request that runs out of time is announced once as waiting in the terminal (#34, #35, #36)
- The switch with three positions in the panel (Im Deck, Automatik, Im Terminal, with a sentence about the chosen one) and the wait time as a slider from 30 seconds to 9 minutes; the daemon confirms every change to all UIs (#37)
- Presence on the Mac: the app measures the frontmost app (bundle path, which the daemon compares with the processes above an agent), idle time, screen lock (distributed notifications) and Focus (`INFocusStatusCenter`, only with the user's yes, else "no Focus") without any special permission, and reports changes at once and a heartbeat every 15 seconds (#33)
- System notifications with buttons: a held request shows Erlauben and Ablehnen, a shortened one Ansehen (opens the panel) and Ablehnen, waiting in the terminal and done show no buttons; "always allow" is never in a notification; a notification goes when the request is answered elsewhere, an old button cannot answer a newer request, allow from a notification never allows a shortened request (#32)
- Request card in the panel: held (Erlauben, Ablehnen), shortened (Ansehen, Ablehnen, Erlauben only after the full text was shown, the app and the daemon both check it), waiting in the terminal (dashed, no buttons); "Immer erlauben" small and apart with rule and target in words, a broad target (repo, all projects) in amber (#30, #31)
- Tray panel (mockup "Tray-Panel"): agents in the fixed order with the marks of each state (circle, rounded square, ring, diamond, dash; color never alone), time since the last change, branch and activity, context bar, Codex tag, amber badge with the number of waiting agents. Colors from the mockups, adaptive to light and dark. Tests draw the panel into pictures (#29)
- App icon (`AppIcon.icon`, Icon Composer layers: three panes as in the family, four tiles with the amber one at the top right) and menu bar symbols that follow the appearance of the menu bar; tests draw the symbol under light and dark and read the pixels (#28)
- Mac app scaffold `apps/AmiscaraDeck` (xcodegen, SwiftUI menu bar app without Dock icon): the symbol in two states (calm, amber tile when an agent waits), the app finds the daemon and starts the embedded one when none runs, reconnects with growing pauses, shows a first list of agents. Model, order and wording are tested (12 tests), CI builds and tests the app on the Mac runner (#27)
- `deck-ffi`: the UniFFI hull for the Mac app. `DeckConnection` (connect, answer allow or deny, settings, presence, close) with a `DeckObserver` for state and every change, hook status, install and uninstall; the types mirror the protocol one to one, no logic. `scripts/build-ffi.sh` builds `DeckFFI.xcframework` and the Swift bindings into `apps/AmiscaraDeck/Generated` (#26)
- M1 acceptance against the real Claude Code (`spikes/m1/e2e.py`, findings in `docs/befunde-m1.md`): session visible, allow from the command line without touching the terminal, terminal first, daemon killed while a request is held (#98)
- State across restarts: the daemon writes agents, settings and the request counter to `state.json` (0600, replaced in one step, every second when something changed, at stop) and reads it at start; open requests come back as waiting in the terminal, ids are never used twice, ended agents expire, a broken or newer file means an empty start. `amiscara-deck daemon install|uninstall|status` starts the daemon at login with a LaunchAgent (#22)
- `deck-sim` and `amiscara-deck sim`: simulated agents built from the recorded hook inputs, scenarios `demo`, `permission` and `busy`, played against a running daemon at any speed without spending tokens (#23)
- Holding and answering: while a UI is connected the daemon holds each PermissionRequest of Claude Code until the user answers (allow, deny with message, always allow with an offered rule), the time runs out (1 to 540 seconds, default 120), the terminal answers first, the last UI leaves or the daemon stops; nobody can make it print anything but a PermissionRequest answer. UIs set the mode and the wait time. New command `amiscara-deck answer`, and `list` shows the open request. A shortened card can only be allowed when the UI says it showed the full text (`expanded`); the daemon refuses otherwise, and the command prints the whole text and needs `--seen` (#21)
- `deck-daemon`: tests for PermissionRequest at the service level: answered at once with nothing until holding comes, shown to UIs as waiting in the terminal, cleared by the next event, kept for UIs that connect later, never held for Codex (#20)
- `deck-client` and the commands `amiscara-deck list` and `watch`: the daemon streams every change to connected UIs (full state first, slow UIs are dropped, UIs are told when the daemon stops), the client keeps the state, the command line prints a table or one change per line, `--json` for scripts; text from outside is shown with hidden characters escaped (the check moved to `deck-proto::text`, shared with the request cards) (#19)
- `deck-hooks`: install, uninstall and status of the hook entries in `~/.claude/settings.json`; idempotent, foreign entries and order stay, backup before every change (last five kept), replaced in one step, invalid or oddly shaped files are never touched (#17)
- `deck-hook`: tests for every failure (no socket, nobody listening, connection cut, answer cut, time out, invalid answers, too big input) and for the real binary: nothing printed, exit code 0 (#16)
- `deck-hook`: reads the hook input, adds herdr and tmux pane, terminal and the chain of parent processes, hands it to the daemon, waits for the answer to a PermissionRequest only, and ends silently with exit code 0 on every error; the data folder paths moved to `deck-proto` (#15)
- `deck-daemon`: the service `amiscara-deckd` with a Unix socket (0600 in a 0700 folder), intake of hook messages into the session state, branch from `.git/HEAD`, takeover of stale sockets, refusal of a second daemon (#14)
- `deck-session`: replay tests over the real M0 samples (whole sessions, repeats, wrong order, interleaved sessions, 200 seeded shuffles with invariants) (#13)
- `deck-session`: life of a permission request (held, passed through, answered), deadline, release of the waiting hook, answers with "always allow" from an offered rule only, card cleared by the next event of the same agent; writing tools show what they write, and characters that can hide text (found by Unicode category) force expanding and are escaped in summary and full text as `⟦U+202E⟧` (a typed `⟦` is doubled, so escapes cannot be faked), writing tools always need expanding and show their options (#12)
- `deck-session`: state machine for agents as pure functions (status, activity, subagents, paused, ended agents expire after 10 minutes) (#11)
- `deck-proto`: agent, request and status types and the messages between hook program, daemon and UIs, with protocol number, host name and a JSON-lines codec (#10)
- `deck-proto`: tolerant hook input types for all events, permission suggestions with the raw value kept, and the PermissionRequest answer; tests against the M0 samples (#9)
- Rust workspace with the crates from the concept, workspace lints and CI for format, clippy and tests (#8)
- M0 spikes against the real Claude Code and herdr: capture hook, pty driver, scenarios (`spikes/m0/`), sanitized hook samples (`testdata/hooks/`), herdr API schema, findings in `docs/befunde-m0.md` (#2, #3, #4, #5, #6, #7)
